# M7 — Theming v2: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A professional, modern default look; theme values that bind to the host site's design tokens (`var(--…)`); optional Google Font loading; light/dark mode with both media-query and forced modes; multi-brand organization (issue #117).

**Architecture:** The theme document grows back-compatibly (new optional fields only). The viewer stops writing `--gt-*` inline directly and instead writes paired `--gt-light-*` / `--gt-dark-*` inline; the stylesheet maps them onto `--gt-*` per color scheme. All defaults keep flowing from the single `src/queries/defaults.ts` source.

## Design brief (binds Task 3's stylesheet work — Storylane-inspired, owner-approved direction)

- **Palette (light):** accent `#7c3aed` (violet-600); surface `#ffffff`; text `#0f172a` (slate-900); overlay `#1e1b4b` at high opacity for backdrops. Muted borders `color-mix(accent 12%, transparent)`-style subtlety.
- **Palette (dark defaults):** surface `#0f172a`; text `#f1f5f9`; accent `#a78bfa` (violet-400 — keeps contrast on dark); overlay `#020617`.
- **Shape:** radius default 12 (theme-controlled); CTA/start/Next buttons are pill-shaped (`border-radius: 999px`) regardless of `--gt-radius` (cards/tooltips use `--gt-radius`).
- **Depth:** tooltips/overlays/modal get soft layered shadows (`0 4px 6px -1px rgb(0 0 0 / 0.1), 0 10px 24px -8px rgb(0 0 0 / 0.18)`); 1px borders in a low-alpha text color; no hard outlines.
- **Type:** default `--gt-font-family` becomes `'Inter', ui-sans-serif, system-ui, -apple-system, 'Segoe UI', sans-serif` (STACK ONLY — no network fetch unless a googleFont is set); headings 600 weight, slightly tight letter-spacing (-0.01em); body 15px/1.55.
- **Controls:** primary buttons accent-filled white-text with hover brightness shift; secondary = transparent with 1px accent-mix border; visible `:focus-visible` rings (2px accent, 2px offset) everywhere; hotspot pulse ring softened (lower alpha, slower).
- **Progress:** thinner (4px), pill, accent on a 12%-alpha accent track.

### Task 1: Theme schema v2

**Files:** Modify `src/schema/theme.ts`; Create `src/schema/cssValue.ts` (shared validator helper); Test extend `test/schema/documents.test.ts` (or theme-specific file)

- New shared validator: `cssColorValue` — accepts 6-digit hex (`#rrggbb`, case-insensitive) OR `var(--token)` / `var(--token, <fallback>)` where token matches `[a-zA-Z0-9-_]+` and fallback is any short string without `)` nesting (single regex, exported for tests): `/^(#[0-9a-fA-F]{6}|var\(--[\w-]+(\s*,\s*[^)]{1,64})?\))$/`. Error message explains both forms.
- Color fields (`accent`, `surface`, `text`, `overlay`) switch from the hex-only regex to `cssColorValue`. Descriptions updated: "Hex color or a CSS variable from your site, e.g. var(--brand-primary)".
- New `dark` object field (optional, collapsible): optional `accent`/`surface`/`text`/`overlay` (same validator) — description: "Optional dark-mode overrides; fields left empty fall back to sensible dark defaults".
- New `googleFont` string (optional): description "Google Font family name, e.g. Inter or Manrope — loaded by the viewer unless disabled; leave empty to use the site's font stack". Validation: max 40, matching `GOOGLE_FONT_NAME_PATTERN` (`/^[A-Za-z0-9 ]+$/`) — the pattern is a shared export from `src/queries/defaults.ts` so the VIEWER re-validates at consumption time (Studio validation doesn't bind Content-API writes; see Task 3's loader).
- New `brand` string (optional): organizational label; shows in the preview subtitle; add an ordering by brand.
- `fontFamily` keeps meaning a raw CSS font-family value (takes precedence over googleFont's family when both set — document in both descriptions).
- initialValues still from `THEME_DEFAULTS` (Task 2 modernizes the values — this task only imports).

TDD: validator unit cases (hex ok, VAR ok with/without fallback, rejects `var(foo)`, nested parens, rgb(), empty); field presence; dark object members optional; googleFont regex; back-compat (no new required fields).

### Task 3: Viewer — light/dark architecture, font loader, redesign

**Files:** Modify `src/react/theme.ts` (rework), `src/react/GuidedTour.tsx` (+ `colorScheme?: 'auto' | 'light' | 'dark'` prop, default 'auto'; font loader effect), `src/react/styles.css` (mapping + full visual redesign per the design brief), `src/react/types.ts`/`index.ts` (prop surface); Create `src/react/fontLoader.ts`; Tests: theme.test.ts rework + new fontLoader tests + GuidedTour scheme tests; axe re-run (contrast rules stay non-computable headlessly, but structure states re-verified)

**Custom-property architecture (exact):**
- `themeToStyle(theme)` now emits `--gt-light-accent`, `--gt-light-surface`, `--gt-light-text`, `--gt-light-overlay` (theme values or nothing — stylesheet defaults cover absence), `--gt-dark-accent` etc. (from `theme.dark?.x ?? THEME_DARK_DEFAULTS.x` — ALWAYS emitted when a theme exists so dark mode works even for themes authored before dark support; when theme is null emit nothing), plus radius/hotspot-size/font-family as today (scheme-independent).
- `styles.css`:
  ```css
  .gt-tour {
    --gt-accent: var(--gt-light-accent, #7c3aed);
    --gt-surface: var(--gt-light-surface, #ffffff);
    /* …text, overlay… */
  }
  @media (prefers-color-scheme: dark) {
    /* auto mode ONLY — mutually exclusive with the forced rules below, so
       cascade order can never matter (a specificity tie between overlapping
       selectors would be order-fragile) */
    .gt-tour:not([data-gt-scheme]) {
      --gt-accent: var(--gt-dark-accent, #a78bfa);
      /* … */
    }
  }
  .gt-tour[data-gt-scheme='dark'] {
    --gt-accent: var(--gt-dark-accent, #a78bfa);
    /* … */
  }
  /* forced light needs no rule: the base .gt-tour mapping IS light, and the
     auto media rule excludes any node carrying data-gt-scheme */
  ```
  `colorScheme: 'auto'` renders NO `data-gt-scheme` attribute; `'light'`/`'dark'` set it — the selectors are disjoint by construction.
  Literal fallback values in styles.css must equal the defaults-module constants (extend the existing parity test to cover light AND dark sets).
- `colorScheme` prop → `data-gt-scheme` attribute (`auto` sets none). Consumers with their own toggle pass 'light'/'dark'; `var(--gt-accent)` overrides via the `style` prop still win (inline custom property beats stylesheet mappings — document that consumer overrides are scheme-INdependent unless they use the light/dark pair).
- **Font loader** (`fontLoader.ts`): `ensureGoogleFont(family: string): boolean` — **re-validates `family` against the shared `GOOGLE_FONT_NAME_PATTERN` before ANY interpolation** (Studio validation doesn't bind API-written documents — an unvalidated value would flow into a URL and a CSS custom property, an injection vector). On mismatch: no-op, return false, dev-only console.warn. On match: idempotent per family (module-level Set), SSR-guarded, appends one `<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=<encodeURIComponent'd>:wght@400;500;600;700&display=swap">` to `document.head` + the two preconnect links once. Called from a GuidedTour effect when `tour.theme?.googleFont` is set AND `props.loadGoogleFont !== false` (new prop, default true). themeToStyle applies the SAME pattern gate before emitting `--gt-font-family: '<family>', <default stack>` (single-quoted; the pattern excludes quotes/parens by construction). Tests cover the malicious-value path (URL-ish and quote-bearing strings → rejected, no DOM mutation, no custom property).
- **Visual redesign** of styles.css per the design brief (buttons, tooltips, overlays, progress, dots, chapter menu, lead form, outro, modal, embed button). Keep every class name and DOM contract unchanged — this is a CSS-only restyle plus the scheme mapping. `prefers-reduced-motion` and containment/tooltip-width sections preserved.

TDD: themeToStyle pair emission incl. always-emitted dark set + null-theme nothing; scheme attribute wiring; fontLoader idempotence/SSR/opt-out (spy on document.head); parity light+dark; existing suite green (class names unchanged should keep component tests passing).
