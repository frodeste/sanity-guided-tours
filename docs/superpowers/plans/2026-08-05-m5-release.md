# M5 — Release: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Everything 1.0.0 needs except the button-press: docs a stranger can follow, a seedable demo (including the meta tour that teaches the plugin), and a verified release pipeline. **The npm publish itself is NOT part of this plan** — it is presented to the owner as a decision at the end and never executed autonomously.

**Architecture:** Docs and seed content are additive. The release pipeline follows spec §11 (semantic-release, conventional commits, npm provenance) and is verified by dry-run only. Meta-tour screenshots come from Playwright captures of the real Studio components rendered with fixture props in a local harness (no Sanity auth needed) — owner-supplied captures of the live Studio can replace them later.

**Tech Stack:** unchanged + `semantic-release` toolchain, Playwright (capture only, devDependency-free — invoked via bunx in a script, not added to package.json deps).

## Global Constraints

All M1–M4 constraints hold (memory `guided-tours-m1-execution-facts`). Additions:
- **HARD GATE: no `npm publish`, no `semantic-release` in non-dry-run mode, no git tags pushed.** Any step that would publish stops and reports instead. `release.yml` triggers only on `workflow_dispatch` until the owner flips it (documented in the workflow comment) — NOT on push to main, so merging M5 cannot accidentally publish.
- README claims must match reality (verify every command and code sample against the current package before writing it down — the props table comes from src/react's actual exports, config options from src/config.ts).
- Seed script must work against ANY project/dataset via env vars (`SANITY_PROJECT_ID`, `SANITY_DATASET`, `SANITY_TOKEN`) — never hardcode the demo project.
- The version field stays `0.0.0-development`.
